# «In-Memory кэш с фоновой очисткой и защитой от Thundering Herd» (Singleflight)

Очень сильная архитектурная задача. Идеально подходит, если хочется удивить учителя глубоким пониманием конкурентности.

Условие: У нас есть медленная база данных (GetFromDB(key string) занимает 500 мс). К нашему сервису одновременно приходят 50 горутин с запросом одного и того же ключа.

Задача:

1. Реализовать кэш с TTL (временем жизни записи).
2. Запустить фоновую горутину-сборщик мусора на time.Ticker, которая удаляет протухшие ключи (и корректно останавливается при закрытии кэша).
3. Главное усложнение (паттерн Singleflight): Если 50 горутин одновременно запросили ключ "user:42", которого нет в кэше, в базу данных должен уйти только 1 запрос, а остальные 49 горутин должны подождать его результат (через закрытие персонального канала chan struct{}) и получить готовые данные.

Что тренирует: time.Ticker, тонкую синхронизацию через закрытие каналов как broadcast-сигнал для десятков горутин, защиту от гонок данных.
