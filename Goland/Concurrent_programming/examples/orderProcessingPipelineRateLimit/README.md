# Задача: «Воркер-пайплайн с таймаутом и отменой»

Условие

Представь, что ты пишешь сервис обработки входящих заказов.
Тебе нужно реализовать систему из трех этапов (конвейер / pipeline), связанных через каналы:
1. Генератор заказов (Producer):
	• Создает структуру Order (например, с полями ID int и Amount float64).
	• Генерирует, допустим, 20 заказов с небольшими случайными задержками (через time.Sleep) и отправляет их в первый канал.
	• После генерации всех заказов обязан закрыть этот канал.
2. Воркеры обработки (Workers):
	• Запускаются в нескольких горутинах (например, 3 воркера).
	• Читают заказы из входного канала, «обрабатывают» их (эмулируй работу через time.Sleep(500 * time.Millisecond))
		и отправляют результат (структуру Result с полем Success bool и ошибкой, если есть) во второй канал.
	• Важно корректно завершить работу воркеров, когда входной канал закрыт и в нем больше нет данных.
3. Сборщик результатов и контроллер (Collector / main):
	• Собирает результаты из выходного канала и выводит итоговую статистику (сколько успешно, сколько с ошибкой).
	• Дополнительное усложнение (самое полезное): Добавь общий контекст (context.WithTimeout или context.WithCancel) или отдельный канал quit/done, чтобы по истечении, например, 3 секунд или по нажатию сигнала завершения программа прерывала обработку всех горутин без зависаний и утечек (goroutine leak).

На что обратить внимание при решении

• Что происходит, если попытаться отправить данные в закрытый канал? А прочитать из закрытого?
• Как правильно использовать конструкцию for ... range для чтения из канала?
• Убедись, что ни одна горутина не зависнет навсегда (используй флаг -race при запуске: go run -race main.go).
