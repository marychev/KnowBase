# Uvicorn workers (воркеры)

UVICORN_WORKERS —  независимые рабочие процессы (processes) операционной системы, которые Uvicorn запускает для параллельной обработки входящих HTTP-запросов к асинхронным Python-приложениям.

## Основные аспекты:

- Многопроцессорность: В отличие от одного процесса, несколько воркеров (--workers) позволяют не блокировать работу при высокой нагрузке.
- Управление: Один процесс-менеджер Uvicorn слушает порт и распределяет запросы между рабочими процессами (воркерами).
- Использование: Запускаются командой `uvicorn main:app --workers 4`.
- Рекомендация: Для продакшна часто рекомендуют использовать Uvicorn вместе с Gunicorn для более стабильного управления воркерами
- что делает: запускает N независимых процессов приложения, каждый со своим event loop
- зачем: обойти GIL Python и задействовать несколько ядер CPU
- как масштабируется: каждый воркер = +1 процесс в памяти, делит порт через SO_REUSEPORT
- типичное значение: 2 × CPU_cores (для CPU-bound) или = CPU_cores (для I/O-bound с asyncio)
- на 2 ядрах: разумно 2–4; больше — рост context-switch без выигрыша
- где используется: uvicorn app:main --workers $UVICORN_WORKERS или в CMD Dockerfile


## Расчет количества воркеров (workers) для Uvicorn 

Расчет количества воркеров (workers) для Uvicorn зависит от характеристик сервера (CPU) и типа нагрузки вашего приложения (I/O-bound или CPU-bound)

### Основная формула
Общепринятая рекомендация для Uvicorn (и Gunicorn с UvicornWorker):
```
Workers = (2 x vCPU Cores) + 1
```
_Пример: Если у вас сервер с 2 ядрами (vCPU), формула дает (2 x 2) + 1 = 5 воркеров._

#### CPU-bound задачи (тяжелые вычисления):

Если приложение занято вычислениями (обработка изображений, видео, тяжелая математика), ставьте 1 воркер на 1 ядро (или даже меньше), так как процессы будут конкурировать за ресурсы CPU.
